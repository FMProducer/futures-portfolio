## 5. Независимая бухгалтерская диагностика текущей версии

### 5.1. Фиксированные входы и область проверки

Все семь прогонов использовали сохранённый `config_snapshot.json`, SHA256 `a36326f89408362eaeb2e5e72686946f4bf796b53bfbf31b21fdc23fa1c24d2c`, весь локальный ряд каждого символа, `live_mode=False`, `since=None`, `until=None`, commission=0.0004, slippage=0.0005. Значения fees/slippage — существующие default движка, а не настройка по результату.

Снимок: начальный капитал 1000, доли 25/25/50, плечи 7/7/1, общие surplus/deficit=0.031, trailing distance=0.04, FUSE=false, legacy_constant funding. Equity trailing в этом снимке включён: activation=7%, distance=0.3%, timeout=40s. Config отличается от раннего обсуждения бумажного лога; его значения не переносились из памяти и не менялись для теста.

Без timestamps это только диагностика последовательности строк. Она не устанавливает день рынка, время funding, причинность scanner или допустимость внутридневной стратегии. Статус accounting PASS означает соблюдение проверенных арифметических тождеств, а не экономическую приемлемость результата.

### 5.3. Что проверено арифметически

На 10 117 сохранённых accounting checkpoints независимо пересчитаны:

`actual = CASH + margin_LONG + margin_SHORT + unrealized + VIRTUAL + SAFE`

`expected = ledger_base + realized + unrealized − fees − funding_paid − liquidation_loss`

Максимальная абсолютная невязка — `3.5e-24`, ниже существующей погрешности движка `max(1e-6, abs(expected)*1e-9)`. CASH неотрицателен во всех наблюдавшихся checkpoints. Проверены неизменность hashes кода/config/плана/CSV и всех 157 входов, а также согласованность финального equity со снимком состояния.

Отдельные assert проверили state-level B1: credit +0.125 и debit −0.25 изменяют V/equity с правильным знаком, CASH остаётся прежним, residual=0. Это не приёмка receipts, dedup, WAL или crash recovery. Основные семь прогонов использовали legacy_constant, а не B1.

### 5.4. Существенные наблюдения и ограничения движка

1. **Нет обязательного terminal close.** Final TPV отражает открытые остатки. У TST +0.13239% превращается в −0.23921% после оценки выхода. Для build-only 1000BONK расходы выхода добавляют около 3.1829 USDT: −0.37460% → −0.69289%.
2. **MaxDD не всегда включает opening capital.** `history` начинается после формирования портфеля, затем движок считает peak по history. Для 1000BONK MaxDD=0.0667526%, а с исходными 1000 USDT в начале кривой — 0.3748185%. Для DUSDT: 79.300067% → 79.316277%. Остальные расхождения малы, когда поздний peak превысил initial capital. Это подтверждённый дефект метрики для полного жизненного цикла; код не исправлялся в рамках аудита.
3. **Legacy funding не равен реальным funding cashflows.** На каждом баре списывается положительный drag по gross notional обеих ног: daily rate=0.0002 /1440. Без timestamps этот механизм не проверяет settlement; равные LONG/SHORT не компенсируют друг друга в такой модели. Разрешение менять funding policy не получено.
4. **NIL старого sweep не воспроизведён.** В текущем ряду с текущим config на баре 345 возникает модельная predictive liquidation, затем cooldown/rebase на 489; stop на 528 и новый rebase на 672. Финальная equity=7.597291 USDT, один модельный liquidation event. Это не доказательство биржевой ликвидации и не объяснение исторических −102.05% без исходного config/traces.
5. **Rebase меняет `state.initial_capital`.** Сохранённый original initial capital нужен для сквозных процентов; ledger_base и cumulative realized/fees сохраняются отдельно. Проверенные арифметические тождества не заменяют проверку экономической допустимости каждого rebase.
6. **Циклы не равны торговым round trips.** Счётчик увеличивается в ветке обработки actions; `rebalance_log` записывается только при новых fills. Два биржевых fills первоначального build дают один цикл; это не «полное отсутствие торговли».
7. **Модель исполнения ограничена.** Основной цикл использует close ряда; step size жёстко 0.001 для любого symbol, MMR=0.004, без исторических contract filters, tier schedules и mark-price. Такие результаты не подтверждают биржевую исполнимость и запас ликвидации.
