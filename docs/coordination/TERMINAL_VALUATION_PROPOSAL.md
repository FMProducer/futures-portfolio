## Проблема

historical.replay и comparison.hold завершаются с открытыми LONG/SHORT. Net OPEN_MTM включает entry/rebalance fees и funding, но не цену выхода и exit fees. Поэтому даже одинаковая методика OPEN_MTM у двух arms не отражает одинаковую стоимость ликвидации: их конечные количества различаются. ACCOUNTING_SPEC_V3 §4.1, §Б.7 и требование заранее определить обработку открытых позиций требуют явного правила до OOS; текущий draft оставляет его открытым.

## Предлагаемое правило только для candle research

1. Сохранить прежние result/curve OPEN_MTM без изменения baseline. Добавить отдельно маркированный terminal closeout результат candidate и hold. Не заменять исторические файлы и не переименовывать старый OPEN_MTM в flat.
2. Сначала применить все события funding, принадлежащие текущему окну по существующему порядку replay. Точка оценки — последний close исходного окна. Для свечи это торговая цена-прокси, а не независимо полученный mark или bid/ask.
3. Для иллюстративного полного выхода использовать уже явно заданные research spread/slippage/fee. Пусть M — последний close, h=(spread_bps/2+slippage_bps)/10000. LONG продаётся по M×(1−h), SHORT покупается по M×(1+h). У каждой ноги полный конечный qty; взаимное неттирование LONG/SHORT для уменьшения расходов не допускается.
4. Из OPEN_MTM Equity прибавить корректировку qL×(sell−M)+qS×(M−buy), затем вычесть только новые exit fees=(qL×sell+qS×buy)×fee_rate. Equity_flat−initial_capital есть Net_flat. Старые fees/funding/realized повторно не вычитать и unrealized дополнительно не прибавлять: он уже внутри Equity.
5. Для реализации через Portfolio закрыть обе ноги на detached copy, REDUCE каждой ноги с отдельным receipt; для этой терминальной операции запрет прибыльности обычного rebalance не применяется. Это явно вынужденное расчётное завершение опыта, а не новый сигнал стратегии. Сохранить отдельные exit fills, итоговые qty0/margin0 и сверку Equity с формулой. Исходный state не менять.
6. Существующую close-mark drawdown оставить отдельной метрикой. Если строится новая curve с выходом, включить финальный результат выхода в просадку от того же исходного капитала и ранее достигнутого peak; не утверждать, что close-only curve измеряет intrabar drawdown. Не переносить старый drawdown на новый terminal convention автоматически.
7. Синтетическое исполнение маркировать SYNTHETIC_CANDLE_CLOSEOUT. Нулевые qty не требуют fills/fees. Неполные данные, несовместимые qty/step или недопустимые costs блокируют расчёт. Политика настоящего market close, reduceOnly/hedge-mode, dust, filters, partial/cancel/UNKNOWN, depth и ликвидация остаются отдельным адаптером: синтетическое full fill не подтверждает биржевую исполнимость.

Fee_rate/spread/slippage здесь — только прежние исследовательские входы; новые live numbers не задаются. Дополнительное время на закрытие и funding за пределами окна не моделируются. Реальная длительность выхода потребует собственного timestamp/depth/funding контракта.

Стресс удвоенного slippage по §4.1 должен быть отдельным заранее зарегистрированным replay всего окна с изменёнными издержками, включая входы/ребалансировки/выход. Одна терминальная поправка к результату обычного replay не считается таким стресс-тестом. В этом этапе стресс не запускался.

## Граница решения

Предлагается утвердить пункты1–7 как отдельный режим offline candle research с сохранением OPEN_MTM baseline. После явного решения можно реализовать функцию на копии Portfolio, matched exits и fault tests, один fixed backtest конечного кандидата, отчёт и STOP. PF/cycle, выбор24/6месяцев и числовой live profile этим решением не утверждаются. Даже после внедрения candle closeout исполнение и допуск остаются неподтверждёнными.

Решение User получено для пунктов1–7 offline-методики; реализация передана отдельно в IMPLEMENTATION_SYNTHETIC_CLOSEOUT.md. Это решение не является утверждением полного admission profile или разрешением live-торговли.
