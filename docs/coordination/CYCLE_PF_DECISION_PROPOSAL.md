## Рекомендация для первичной offline-реализации

Предлагаю явно утвердить полный портфельный эпизод как консервативную исходную единицу и честно возвращать INSUFFICIENT_CYCLES, когда непрерывная стратегия не даёт нужных наблюдений. Это не предложение периодически закрывать позиции ради счётчика и не команда изменить торговые сигналы. Если нужна иная единица для непрерывной ребалансировки, сначала требуется отдельное решение о её экономическом завершении и группировке.

Предлагаемые правила эпизода:

1. Эпизод начинается с первой открывающей позиции из flat. Все исполнения одного входа/выхода, включая partial fills, относятся тому же эпизоду. Он заканчивается только после flat обеих ног, подтверждения всех относящихся fills/fees/funding и отсутствия pending/UNKNOWN. Пока результат неизвестен, эпизод не завершён. В текущем offline режиме входы полные, pending/UNKNOWN не моделируются.
2. PnL эпизода — изменение Equity между flat-точками за вычетом подтверждённых внешних денежных потоков. Trading fees/funding уже внутри Equity и повторно не вычитаются. Для текущего candle research external flows отсутствуют; их поддержка не объявляется реализованной.
3. Natural и synthetic terminal завершения помечаются раздельно. Synthetic closeout включает весь оставшийся отрицательный/положительный inventory и exit costs в исследовательский результат; он не создаёт реальные циклы для30-наблюдений карантина и не является биржевым исполнением. Принудительное завершение окна не разделяется на отдельные циклы LONG/SHORT.
4. Для исследовательского PF использовать все завершённые эпизоды этого прогона, включая отдельно помеченный synthetic terminal, с единым определением costs. Gross_profit=sum(max(PnL,0)), gross_loss=−sum(min(PnL,0)); PF=gross_profit/gross_loss только при наличии и положительных, и отрицательных эпизодов. Число natural/synthetic/zero/open эпизодов и причины неопределённости выводить отдельно. PF нельзя трактовать как доказательство независимости эпизодов.
5. Нет эпизодов, нет убытков или нет прибыли: PF=null со статусом причины, никакого автоматического PASS. При наличии только убытков отдельно показать diagnostic ratio0, но это не PASS. Новый произвольный минимальный sample size здесь не задаётся; количественные требования договора сохраняются.
6. При незакрытом terminal inventory итоговые Equity/Net/drawdown остаются видимыми; admission не рассчитывается из PF по одному выигрышному закрытому фрагменту. Для полного research-PF использовать уже утверждённый synthetic closeout или явно сообщать незавершённость результата.

Применительно к рассмотренному опыту эта рекомендация дала бы один synthetic завершённый эпизод сNet7.81013594056799999999999USDT, ноль natural завершений иPF=null (нет убыточных эпизодов). Это условное следствие предлагаемых правил, не новая рассчитанная или принятая метрика. Даже24месячный replay непрерывной позиции может дать только один такой эпизод и не выполнить PF gate; положительный Net этого не исправляет.

## Решение User и следующий scope

Требуется выбор: утвердить правила1–6 портфельного эпизода для первичной offline-реализации либо выбрать модель закрытых долей inventory и отдельно определить её grouping/funding/fees. Выбор временных Equity intervals также потребует явного изменения смысла метрики; он не принимается по умолчанию.

Определение цикла выбрано приведённым выше решением User; варианты закрытых долей и временных интервалов не выбраны. Дальнейшая реализация полного PF требует оставшихся решений. В коде profit_factor/cycle_definition пока сохраняют прежние значения null/NOT_APPROVED; это статус реализации, а не отсутствие решения о понятии цикла. Суточный public-paper продолжает отдельный замороженный опыт, никакие его параметры/данные не менялись. Реальный риск-профиль, OOS окна и решение о live-допуске остаются отдельными.
