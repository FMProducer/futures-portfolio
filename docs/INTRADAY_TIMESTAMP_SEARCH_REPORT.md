## Пути потери времени в существующем коде

1. `scripts/download_history.py`: ответ klines содержит `time`, затем DataFrame сужается до OHLCV перед `to_feather`.
2. `tools/download_30d.py`: аналогично удаляется `time`; каталог назначения относительно `tools/`, а не корня проекта.
3. `backtest/backtest_rebalance.py`, `download_live_data()`: удаляет `time` перед записью `{symbol}_live.feather`.
4. Scanner строит временной индекс в памяти, но его cache содержит ранжирование, а не архив исходных свечей.

Эти места объясняют возможность потери timestamps. Без исторической команды и raw response нельзя доказать конкретный источник каждого текущего файла. Наличие альтернативного timestamp-preserving загрузчика для ZEC не означает пригодность его данных для других символов.

Только OHLCV, длина ряда, файловая дата или дата коммита не задают однозначную UTC-ось и не доказывают отсутствие пропущенных баров. Поэтому индекс не пересчитывался в даты, а красивые, но неподтверждённые окна не создавались.
