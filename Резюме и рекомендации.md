Что происходит на самом деле

Настоящая ликвидация биржи (wipe всего аккаунта) с текущим конфигом НЕВОЗМОЖНА — у вас cash_reserve_usdt = 100,000 (внешний фри-маржин), а маржа позиций ~8-50 USDT. Порог ликвидации: TPV + 100,000 ≤ maintenance_margin — это никогда не сработает.

Что вы видите в логах как "liquidation" — это срабатывание защитных стопов стратегии:
- max_dd_stop — просадка 50% от realised equity ATH
- trailing_stop — откат 0.26% от пика TPV (после +1.55% прибыли)
- funding_shortfall — накопленный фандинг съел весь кэш + виртуал

---

Конкретные решения

1. Если хотите реалистичную ликвидацию — уменьшите резерв

// В config.json, портфель:
"cash_reserve_usdt": 1000    // было 100000
"paper_account_free_margin": 1000
Тогда maintenance margin ~50 USDT будет сопоставим с резервом, и post-factum проверка на adverse price (high/low бара) реально сработает.

2. Если хотите отключить защитные стопы (для чистого бэктеста)

"max_drawdown_limit": 100.0,        // отключить max DD стоп
"equity_trailing_stop_pct": 0.0,    // отключить трейлинг
"toxic_cooldown_days": 0.0          // отключить кулдауны после стопов

3. Включите предиктивный гард (ранний детектор)

"liquidation_distance_crit_pct": 8.0, // сработает за 8% до ликвидации
"liquidation_distance_warn_pct": 15.0    // предупреждение```
Сейчас оба = 0 → гард выключен.

#### 4. Настройте фандинг (главная причина "тихой смерти" за год)

Проблема: Predictive Guard использует close, а не adverse price

# predictive guard (строка 1259):
cross_liq_dist_pct = state.cross_margin_distance_pct(mid_price, mmr)  # mid = close

# post-factum hard liquidation (строка 1314-1317):
if state.pos_short >= state.pos_long:
    adverse_price = Decimal(str(max(high_prices[i], close_prices[i])))  # high для net short
else:
    adverse_price = Decimal(str(min(low_prices[i], close_prices[i])))   # low для net long

Predictive guard не видит intrabar-движение — срабатывает постфактумом, когда уже поздно.
