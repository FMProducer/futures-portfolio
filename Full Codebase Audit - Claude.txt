Full Codebase Audit - Prosperous Bot Futures Portfolio

Executive Summary

The codebase implements a sophisticated market-neutral futures portfolio rebalancer with paper/real trading modes, supervisor-based swarm management, and extensive safety guards. The architecture is well-structured with clear separation of concerns (calculator, executor, connector, funding, share-trailing, profit-budget). However, there are several critical bugs and race conditions that directly impact production safety and correctness.

---

Critical Issues (Confidence ≥ 80)

1. Config.json Race Condition — Confidence: 95

Files: core/main.py (lines ~130-138, 3365-3370), supervisor/swarm_manager.py (lines 812, 1302-1317)

Issue: Multiple processes write to config.json without file locking:
- main.py bots write toxic_blacklist entries directly to config on liquidation/TS- sblack_list, toxic_blacklist_paper/real, probation entries
- safe_save_json uses temp-file + os.replace (atomic on single writer) but provides no cross-process coordination

Impact: Toxic blacklist entries can be lost when supervisor overwrites config after a bot wrote to it. A liquidated ticker can be re-launched.

Fix: Add file locking (e.g., filelock.FileLock("config.json.lock")) around all config reads/writes in both main.py and supervisor.

2. B3: Exit Flag Doesn't Create Toxic Entry — Confidence: 90

Files: core/main.py (line 69 emit_signal), supervisor/swarm_manager.py (lines 834-886)

Issue:
- main.py emits exit_<mode>_<ticker>.flag on profitable trailing stop (line 421 in mp", ...) for collateral critical, but looking at line 3354+ there's alsoemit_signal("exit", ...) for equity trailing stop)
- swarm_manager.py signal handler (lines 834-886) only processes stop_*.flag — compl
- ROADMAP explicitly documents this as unfixed: "exit-флаг не создаёт toxic-запись — Требует фикса"

Impact: After a profitable TS exit, the ticker is NOT added to toxic_blacklist. It can be immediately re-selected by scanner and re-launched, bypassing the cooldown.

Fix: Add exit_*.flag handling in supervisor signal loop (after line 880) to add ticker to toxic_blacklist with cooldown.

3. B4: HEAL Restarts Bot After Trailing Stop — Confidence: 85

Files: supervisor/swarm_manager.py (lines 230-251, enforce_swarm_consistency)

Issue: Lines 232-251 check trailing_stop_triggered and correctly schedule liquidation + reset TS flags. However, the function continues to to_heal_tickers.add(ticker) logic path if state file passes
validation. The continue at line 251 should prevent this, but the logic flow is compt (line 819) is used later in reconciliation which may reintroduce the ticker.

Impact: A bot stopped by TS can be HEAL-restarted if supervisor restarts before stat

Fix: Add explicit trailing_stop_triggered check at the START of enforce_swarm_consis-stopped tickers, and ensure healed_tickers never includes them.

4. B8: Liquidation Guard Disabled for Cross Margin — Confidence: 95

Files: core/main.py (lines 1276-1280, 1266-1275), core/connector.py (lines 147-182)

Issue:
- connector.get_position_risk() returns liq_price: 0.0 for CROSS margin (Binance API limitation, line 164)
- main.py lines 1276-1280 explicitly skip the liquidation distance check for real mo
- Only protection is margin ratio check (warning3.0x, critical 1.5x) and max_drawdown_limit

Impact: During extreme moves (e.g., PORTALUSDT +17% in 1h per ROADMAP), positions can be liquidated with zero warning from the liquidation guard. Margin ratio is a lagging indicator.

Mitigation in place: margin_ratio_critical: 1.5 triggers emergency close. But this is reactive, not predictive.

Fix: Implement synthetic liquidation price calculation for CROSS margin: liq_price ≈ mark_price * (1 ± 1/leverage) using position notional and maintenance margin rate (0.4%). Add this as fallback in
get_position_risk or in main.py liquidation check.

5. B7: Qty Asymmetry (LONG vs SHORT) — Confidence: 80

Files: core/calculator.py (line 114-116 val_long/val_short uses entry_price), core/e_limit_order_params uses mid_price), core/main.py (lines 1227-1259)

Issue:
- ROADMAP claims "✅ ИСПРАВЛЕН (07.2026)" via B7 fix using mid_price for qty
- But: calculator.py still calculates val_long and val_short using long_entry_price 4-135) which diverge due to spread/slippage
- This means share calculations use asymmetric notional values, causing perpetual rebalance drift

Impact: Each rebalance cycle accumulates PnL drag from hedge imbalance. After 100+ cycles this can reach 1-3% equity drag.

Fix: Use a single reference price (mark price or mid_price) for BOTH legs' valuation in PortfolioCalculator, or track a unified hedge_entry_price for the pair.

6. Paper Budget SQLite Concurrency — Confidence: 75

Files: core/paper_budget.py (lines 20-90), supervisor/swarm_manager.py (lines 796-801, 994-1003)

Issue:
- paper_budget.py uses BEGIN IMMEDIATE (line 46) for transactions — provides SQLite-
- But supervisor calls reconcile_terminal_allocations (line 797) which opens separate read-only connections (line 126 uri=True mode=ro) while bots may hold write locks
- No coordination for the events table inserts during concurrent reserve/release

Impact: Potential sqlite3.OperationalError: database is locked under high contentionons.

Fix: Add a global lock file (e.g., paper_budget.sqlite.lock) using filelock for all erialize via a single manager process.

7. Funding Model Precision Loss — Confidence: 70

Files: core/funding.py (lines 274-303 apply_funding_paper), core/main.py (lines 1386

Issue:
- apply_funding_paper updates paper_wallet["balance"] and strategy_state["virt_debt"] as float (lines 289-290)
- paper_wallet["balance"] is quantized to 0.0001 at persistence (line 289), but virt
- Funding amounts are tiny (~0.0001% per 8h = ~0.01 USDT on 1000 USDT) — quantization loses precision- funding_paid accumulates as float without quantization control

Impact: Long-running bots accumulate rounding drift between wallet balance and virt_debt, breaking the invariant wallet_balance = cash + virt_debt + positions_value.

Fix: Keep all funding values as Decimal throughout; only quantize at final persistence. Use Decimal('0.0001') quantization consistently.

4. Magic numbers — Many hardcoded thresholds in config.json (e.g., equity_trailing_stop_timeout_sec: 34.454466312271094)

What's Not Checked / Remaining Risks

What's not fully verified:
- Live end-to-end integration (requires Binance API keys)
- PM2 process management under supervisor restarts
- WebSocket feed integration (planned in ROADMAP 5.8, not implemented)
- Multi-account / sub-account isolation

Remaining risks:
1. Config race condition — Can cause silent data loss in production
2. Cross-margin liquidation blind spot — No predictive guard for 50%+ of margin mode
3. Exit flag gap — Profitable exits don't trigger cooldown, enabling churn
4. Qty asymmetry — Structural PnL drag that compounds over time

---

Summary

The codebase is production-grade in architecture with strong financial modeling, coment test coverage. However, 3 critical bugs (config race, exit flag, cross-margin liq) and 2 high-impact issues (qty asymmetry, paper budget concurrency) must be fixed before scaling to multiple REAL bots with significant capital.

Recommended immediate action: Implement file locking for config.json and add exit flag handling in supervisor — these are 2-4 hour fixes that eliminate the highest-risk failure modes.
